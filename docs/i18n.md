# TecnoMath — internacionalización global

TecnoMath usa `js/i18n.js` como runtime central y `locales/index.json` como registro de idiomas.

## Comportamiento

- Selección inicial: idioma guardado → idioma del navegador → español.
- Persistencia: `localStorage.tecnomath_language`.
- Fallback seguro: español y, si una clave no existe, la propia clave como último recurso interno.
- Lazy loading: cada JSON se carga solo cuando se necesita y se conserva en cache del runtime.
- RTL preparado para árabe, hebreo, persa, urdu, pashto, kurdo y sindhi.
- Variables: `window.TecnoMathI18n.t('score.points', { points: 100 })`.
- Selector global: el runtime lo monta automáticamente.

## Marcado traducible

```html
<button data-i18n="common.play"></button>
<input data-i18n-placeholder="common.search">
<button data-i18n-title="accessibility.languageSelector"></button>
```

Para contenido creado por JavaScript, ejecutar `window.TecnoMathI18n?.translatePage()` después de insertar el contenido.

## Juegos

Las mecánicas, controles, puntuaciones, progreso, preguntas correctas y autenticación deben permanecer independientes del idioma. Los textos visibles deben migrarse progresivamente a claves i18n. Los juegos nuevos deben añadir sus locales sin duplicar el juego.

No se inventan traducciones educativas. Un idioma registrado sin archivo propio utiliza el fallback español hasta que exista una traducción revisada.

## Validación

```bash
node scripts/validate-i18n.mjs
```

El validador comprueba el registro, códigos duplicados, idioma/fallback, JSON, claves faltantes y traducciones vacías.

## Integración técnica

La página principal carga el runtime y el service worker existente se encarga de inyectarlo en documentos HTML que todavía no lo incluyan. El service worker conserva su función de caché, offline y sincronización; la internacionalización no modifica Supabase ni sus tablas, RLS, autenticación, progreso, rankings o votaciones.
